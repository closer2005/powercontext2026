## 为什么是 B+ 树
- 页大小 16KB，三层 B+ 树能存约千万级行，一次查找只需 3 次磁盘 IO。
- 非叶子节点只存键和指针，扇出大、树高低；叶子节点用双向链表串起来，范围查询友好。
- 对比 B 树：B 树非叶子节点也存数据，扇出小；B+ 树数据全在叶子，查询路径长度稳定。

## 聚簇索引和二级索引
- InnoDB 主键索引就是聚簇索引，叶子节点直接放整行。
- 二级索引叶子存「索引列 + 主键」；按二级索引查非索引列时，要拿主键回聚簇索引再查一次，叫回表。
- 覆盖索引：查询列都在二级索引里，不需要回表，`EXPLAIN` 里显示 `Using index`。

## 实践
- 最左前缀：联合索引 (a, b, c) 能命中 a、a+b、a+b+c，不能命中 b+c。
- 索引列上做函数或隐式类型转换会失效，例如 `where id = '123'` 同时比较字符串和数字。
- 写多读少的表不要加太多索引，维护成本会反噬写入性能。
